# LoveSpark Agent Audit Ledger

Append-only record of what the agent got **wrong** on each substantive run — the mistake, the **root cause**, and how to prevent it (behaviorally + structurally). Newest entry on top.

**Maintained by a multi-agent audit** (`/audit-ledger` → `workflows/thread-audit-ledger.js`): 5 dimension-auditors comb the run's evidence (the user's verbatim corrections + observed failures) → a **skeptic** drops self-serving overclaims and dedups → a **synthesizer** writes the entry below. Run it after every substantive run/implementation.

> The agent has a bias to under-report its own failures; the skeptic exists to counter that. Findings cite the user's real words as ground truth. Personal/health details are generalized in this public record; agent failures are kept verbatim.

### Recovery pattern

What actually saved the run — copy this: **defense-in-depth framing on injected claims plus mandatory skeptic reproduction.** Spawn prompts labeled all repo-state assertions "PRIOR CLAIMS — may have changed, verify live," and auditors+skeptics live-corrected all three stale claims; the skeptic tier reproduced git history (`git show` of the pre-fix commit) and debunked the tracker auditor's false "introduced-by-today's-fix" causal attribution before it reached the plan. Both recoveries share one shape: never let a downstream agent consume an upstream assertion without the means and mandate to re-derive it. The failures, by contrast, all live where no re-derivation layer existed — the synthesis text, the memory writes, and the phase wiring. The lesson is not "add more agents"; it is "extend the verify-live contract to the orchestrator's own outputs."

### What held up

- Reused the same-day 202-repo meta-audit instead of re-auditing 220 repos (D.O.T.S.).
- Verify-live framing caught all three stale-memory claims; every top-4 dossier skeptic-reproduced end-to-end.
- Judges consumed skeptic-adjusted scores, not raw auditor optimism.
- Rule #15 landed same-turn: plan + automation-log + memory file + MEMORY.md index, unprompted.
- Read-only discipline held across all 28 agents; nothing mutated in any repo.
- Owner-held gates respected: visibility flips, store uploads, and quality-bar calls routed to Joona.

### Prevention rules

1. Absolute-absence claims ('zero X ever', 'never uploaded') require a live check of the authoritative source (dashboard/API/screenshot) or must be written as scoped absence with an [unverified] tag — in deliverables AND memory writes; absence of local logs never proves external-system state.
2. A ranking is not 'done' until the judged set covers (pre-picked ∪ scout-discovered) candidates or every gap has a written exclusion reason; agent-completion counts (28/28, 0 errors) are never a proxy for input coverage.
3. Before multi-lens ranking, declare each composite candidate's member-repo set and assert pairwise disjointness; merge or nest overlapping candidates BEFORE judges score, never after.
4. A 0%-debunk skeptic lane is labeled 'unexercised verifier', never 'clean'; never write 'verified' in a deliverable unless the verifying tier caught a seeded canary or produced organic debunks — and always report the per-lane debunk rate.
5. Read every MEMORY.md-indexed project/feedback file intersecting the candidate repos BEFORE authoring spawn prompts (same-day entries first); memory is a read source at run start, not just a write target at run end.
6. Any orchestrator placement decision outside the scored process (fuse, demote, rank an unjudged candidate) must appear in an explicit 'orchestrator overrides' section; an unjudged candidate never appears in ranked output without a NOT-JUDGED marker.
7. Causal 'introduced-by-X' claims require git evidence of pre-absence (git show/blame of the pre-X state); temporal coincidence is never causation.
8. A standing command or memory rule is broken, not pending, if any script/path it references does not resolve on the default branch of its home repo — name the branch and flag MERGE PENDING until it lands.
9. Every effort/readiness estimate in a decision doc carries its verification depth inline at point of use (static-read | build-green | ran-locally | device-run); checklist-read numbers never silently compete with runtime-verified ones.
10. Print top-level keys before parsing any aggregate JSON, and Read every file immediately before its first Edit — no exceptions for 'known' files like MEMORY.md.

### Prevention rules

1. Every executor claim of a built artifact or test tally must ship with machine-checkable proof (file path + size/hash/mtime, exact command + commit SHA) and be independently reproduced by the verifier or orchestrator before acceptance — prose-only success claims are never sufficient.
2. Executors must run their verification command as the literal last step before writing claim JSON (never from memory of an earlier run) and re-emit the claim with current HEAD SHA after every commit, including trivial follow-ups, so claims always reflect true final repo state.
3. Never route large structured orchestration data (manifests, unit lists, task graphs) through an LLM agent as a relay or reformatting step — embed it directly, and where a model call is unavoidable, assert count-in == count-out and abort the launch on mismatch before execution starts.
4. Any script or state file a long-running workflow depends on for resume must be written to the durable per-project workflow directory from the first launch, never a session scratchpad, and resumeFromRunId must be proven working via dry-run before trusting multi-hour unattended execution.
5. The orchestrator must run every generated unit-instruction set through an explicit compliance check against protected-branch rules (no merge/push to default without review, no force-push) and self-block on any hit — an external permission classifier is a backstop, never the sole enforcement layer for a rule already written down.
6. Ban bare 'done': every spec-required item gets an explicit PASS/PARTIAL/SKIPPED tag with a one-line reason for any non-PASS, the orchestrator diffs the claim against the original spec item list before accepting closure, and items physically impossible to satisfy same-day (e.g. overnight-cron proof) are PARTIAL by definition.
7. Before hand-editing any file that feeds a generator or build pipeline, locate the generator first and patch it or its source — never the generated output — and declare 'no generator found' explicitly before touching the file.
8. Dispatch and build scripts must fail loudly: block any unit whose narrative/spec text does not name its declared target repo, and treat any printed error marker for a required field (e.g. '!! NO PATH') as a non-zero exit, never log-and-continue.

### Prevention rules (→ behavioral memory / CLAUDE.md)
- Treat absence or a sentinel value of a required input as a HARD FAILURE, never a proceed condition: any evidence-fed agent/workflow asserts the payload is present and non-sentinel before doing work, and aborts loudly if not. Never equate 'the run finished' with 'the run was valid.'
- Before creating any feature branch, run a deterministic base check: capture the active branch and run `git rev-list --left-right --count <base>...<active>`; if the active branch is ahead of the intended base, branch off it (or surface the divergence). Never rely on a missing-file tell to discover a stale base; never default to 'main = base' unverified.
- When a routine policy would push third-party / copyrighted / scraped content into version control, stop and re-classify before applying the pattern; name the copyright/storage tradeoff out loud even when the conclusion matches the existing policy.
- Keep sandbox bypass deliberate and named per call: state the specific justification at the moment of each `dangerouslyDisableSandbox` use; never let a prior justification carry the next one by habit.
- When scaffolding a monolith that holds N instances, materialize only the instance(s) with real input data this run; add a sibling niche slot at the moment its data exists, not on anticipation.
