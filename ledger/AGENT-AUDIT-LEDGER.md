# LoveSpark Agent Audit Ledger

Append-only record of what the agent got **wrong** on each substantive run — the mistake, the **root cause**, and how to prevent it (behaviorally + structurally). Newest entry on top.

**Maintained by a multi-agent audit** (`/audit-ledger` → `workflows/thread-audit-ledger.js`): 5 dimension-auditors comb the run's evidence (the user's verbatim corrections + observed failures) → a **skeptic** drops self-serving overclaims and dedups → a **synthesizer** writes the entry below. Run it after every substantive run/implementation.

> The agent has a bias to under-report its own failures; the skeptic exists to counter that. Findings cite the user's real words as ground truth. Personal/health details are generalized in this public record; agent failures are kept verbatim.

### Prevention rules

1. A task that names an artifact in its scope may only be marked COMPLETED after a verify command has run against that exact artifact (xcodebuild for a generated Xcode project, never swift build as a stand-in), with the command and pass output cited per shipped build target.
2. Any repo that ships an Xcode artifact must run an actual xcodebuild of the shipped scheme before a push lands anywhere — swift test plus a generator-drift diff is not a substitute.
3. Any change-set that mutates persisted state-machine flags consumed by another flow must add an orchestration-level test exercising the consuming flow in the SAME change-set, or state an explicit 'no consumer affected' justification, before its gate counts as green.
4. Never chain destructive commands (pkill/rm/kill) with ';' or '&&' in one Bash call, and validate a script's required-argument contract before dispatch — apply the known playbook before the first denial, not after the second.
5. Live macOS verification launches a real .app bundle fronted by bundle id (never a .build/debug binary) and verifies the expected on-screen state change after each interaction batch before reporting the step done.
6. When the same mechanical mutation is performed a third time in one run, script it before the fourth; after any context compaction, re-read every file (even one line) before its first Edit/Write.

### Prevention rules

1. Any schema/engine-behavior fact injected into a spawn prompt's 'trust this' verified-facts block MUST carry a file:line citation obtained by grepping/reading the engine source in the current session; uncited facts must be labeled UNVERIFIED and downstream agents instructed to verify before use.
2. Treat a 0% debunk rate from a skeptic tier (N > ~30 findings) as a red flag: independently re-derive a random sample (>=10% or 10 items) of non-critical confirmations before authorizing fixes, and split reported counts into orchestrator-verified vs skeptic-confirmed-unsampled.
3. Never treat the working tree as trustworthy after a fan-out fix stage: require each fixer agent to emit a DONE sentinel with a per-file manifest, reconcile `git status --porcelain` against the union of manifests, and auto-revert unmatched dirty files before verification or staging.
4. Size fixer fan-outs in bounded waves whose worst-case completion fits the remaining session budget.
5. Define class-fix sweep scope by grepping the entire repo for the defect signature (never by filename convention); re-run the same grep post-sweep and require zero hits before declaring the class closed.
6. Land the class check in the repo's validator in the same commit as the content fix, in every affected repo.
7. Any finding whose truth depends on runtime engine behavior must quote engine source at file:line before it can be marked CONFIRMED; synthesis must diff verdicts across agents keyed by (file, problem-id, claim-class) and hard-fail CONFIRMED-vs-DEBUNKED conflicts into manual adjudication before the fix stage.
8. An autonomous multi-agent run is not closed until its process failures/near-misses are appended to the audit ledger and structural classes filed as known-issues KI entries, with verification that the ledger file actually changed (mtime/line-count delta); the run summary must reference the ledger entries inline.
9. Write the convergence/exit criterion into the workflow design before launching any multi-pass verification loop; never start pass N+1 without an explicit scoping decision citing the pass-N clean/dirty split.
10. Bulk rewrite scripts must deep-compare parsed-before vs parsed-after per file and write only files whose parsed content differs; sanity-check the resulting diff stat against the expected changed-file count before proceeding.

### Prevention rules (→ behavioral memory / CLAUDE.md)
- Never say done/fixed/saved on a visual edit until you have inspected the exact worst-case the user named (brightest frame / white hood) at pixel level — report the measured number, not the action taken.
- Pin the user's stated failure case as the acceptance test; re-check THAT exact case after every change, not a convenient or average sample.
- On HDR/HLG/PQ/Dolby-Vision footage, a blown highlight is a source-interpretation bug until proven otherwise — verify the clip's interpreted color space and apply Rec.709 Override BEFORE grading; never stack an SDR cube on a tone-mapped HDR source.
- When a fix doesn't hold after the 2nd attempt, STOP editing and run a controlled isolation test (off vs on, headless vs in-app) before any 3rd change — repeated failure is proof the hypothesis is wrong, not a cue to tweak again.
- Before calling any edit progress, diff the worst frame against the unedited baseline; if it regressed, report a regression and revert — never frame a regression as a step forward.
- Treat every saved note/asset as an unverified hypothesis: a bare 'remove/disable X' workaround note must be re-diagnosed against the live failing case before acting on it.
- After 3 rejections of the same deliverable OR any user-distress signal ('keeping me up', 'loops', 'want to sleep'), trip a hard stop: state the approach is exhausted, give the single simplest alternative, and ask continue/stop.
- Check for an existing proven asset/tool (gradekit, premiere-grade-bot) and use the one-step path FIRST; DOTS is the default, not a fallback the user has to invoke.
- Never accept a subagent's count/status until you confirm it ran on the canonical current-cut file (path + content fingerprint) and re-count it yourself.
- For batch styling, verify the change covered ALL items (count + start/mid/end), not a sample, and state the coverage ('307/307'); after any SRT import, assert caption-1's in-point equals the source timecode (assume snap-to-zero).

### Prevention rules (→ behavioral memory / CLAUDE.md)
- Treat absence or a sentinel value of a required input as a HARD FAILURE, never a proceed condition: any evidence-fed agent/workflow asserts the payload is present and non-sentinel before doing work, and aborts loudly if not. Never equate 'the run finished' with 'the run was valid.'

Never rely on a missing-file tell to discover a stale base; never default to 'main = base' unverified.
